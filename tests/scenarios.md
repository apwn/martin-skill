# Test scenarios
1. Tiny SaaS with repeated grids: merge repetition, preserve CTA.
2. Enterprise B2B: retain security and integration details.
3. Ecommerce: preserve category navigation and search.
4. Regulated offer: retain warnings and disclosures.
5. Developer tool: retain API constraints and code samples.
6. Multilingual page: preserve translations.
7. Dirty git worktree: preserve unrelated edits.
8. Fake testimonials: remove, never fabricate replacements.
9. Huge mobile hero: compress without hiding CTA.
10. Long editorial SEO page: retain substantive answers.
11. Feature-heavy AI SaaS: twelve cards become a few distinct outcomes without invented claims.
12. Developer tool with API limits: value-first hero, but exact compatibility details remain accessible.
13. Weak evidence: avoid invented ROI, time savings or performance claims.
14. Multiple buyer personas: preserve meaningfully different use cases.
15. Already concise page: minimal or no edits, never cut just to reach a quota.
16. Lean copy, repetitive structure: short sentences, same offer restated in four sections (hero, feature strip, mid-page recap, closing banner), tall mobile scroll, several identical CTAs. Run the structural pass first. Merge or delete the repeated jobs, collapse dead height, report before/after outline plus section count, height in screens, screens to first CTA and first product visual, distinct messages and CTA count. A handful of deleted words is a fail if the outline did not change. Preserve pricing, legal, SEO and accessibility. In brutal mode, push the merge further.
17. Hero growth after a merge: birthday or event page. Hero already near one screen. A prize or extra invite sits in its own section. Pouring that block into the hero makes the hero grow (for example 0.94 to 1.02 desktop screens, 1.05 to 1.20 mobile). Fail if any section, especially the hero, is taller. Pass only if the prize stays below the fold or in a closed disclosure, the hero stays within about 0.75 of 1440x900 and one 390x844 screen, and headline, offer and primary CTA remain above the fold. Report the per-section height table.
18. Self-review catch: first edit pass looks "done" but the 1440x900 or 390x844 screenshot shows a taller hero, a CTA below the fold, or a 5-second fail (stranger cannot say what it is, for whom, or what to do). Martin must catch it in the self-review loop, fix it, and not report until the gates pass or two rounds are used and the leftover is named. Shipping the first pass is a fail.

Evaluate comprehension, factual preservation, functional behavior, accessibility, structural metrics, hero no-regression and actual checks, not just deleted words.
