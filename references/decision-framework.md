# Decision framework

## Structural pass (before copy)
List every section:
- job (what visitor question it answers)
- height in screens (viewport heights; measure if a browser is available, otherwise estimate)
- visual weight (hero / loud / quiet)

Look for: same job twice, proof before the offer, CTA buried, oversized hero, decorative blocks, repeated CTAs or banners, dead scroll (tall blocks that add no new job).

Target outline: fewer sections, order hook → outcome → proof → action. Extra detail can collapse into tabs or accordions, or move to a subpage.

Then KEEP, COMPRESS, MERGE, MOVE or DELETE, or collapse / send to a subpage. Do not start adjective hunting until this map exists.

KEEP: unique, necessary content. COMPRESS: useful but bloated. MERGE: overlapping visitor questions. MOVE: important but poorly ordered. DELETE: duplicate, irrelevant, unsupported or empty decoration. COLLAPSE: still needed, too tall as a full section. SUBPAGE: useful only for a subset of buyers.

For each section ask: What question does it answer? Is it answered elsewhere? Is it specific and true? Does it help understanding, trust or action? Is it in the right place? What would be lost? How tall is it, and does that height earn its job?

High-risk: pricing, eligibility, legal, security, compatibility, navigation, forms. Preserve unless approved. Medium-risk: moving proof, merging important information, collapsing into tabs. Low-risk: repeated vague marketing claims, decorative blocks and filler.

Prefer concrete claims, real product demonstrations, descriptive headings, concise paragraphs, consistent CTA labels, purposeful whitespace. Never enforce a universal word, section or CTA count. Brutal mode means tougher on leftover structure and redundancy, not weaker safeguards.

## Structural success
Measure section count, page height in screens (desktop and mobile), screens until first CTA, screens until first product visual, distinct messages and CTA count. Word count is secondary.

If section count or height moved less than about 15% and the map still shows structural issues, do not ship a small word trim. Either restructure, or say the page is already lean and name what you left. In brutal mode, push further.

## Value-first priority
Map each section to the customer outcome it communicates before deciding whether to keep, compress, merge, move, delete, collapse or send to a subpage. If multiple sections enumerate features but none explains the outcome, rewrite the narrative around defensible value. Keep detailed specifications accessible when they matter.
