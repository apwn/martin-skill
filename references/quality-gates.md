# QA checklist
- [ ] Read repository instructions and git status.
- [ ] Identify page scope and conversion goal.
- [ ] Structural pass before any copy edits: section map with job, height in screens and visual weight.
- [ ] Flag duplicate jobs, wrong order, oversized heroes, decorative blocks, repeated CTAs or banners, dead scroll.
- [ ] Propose a target outline (hook, outcome, proof, action) and restructure to it when editing.
- [ ] No-regression: no section grew, especially the hero. Details went below or into disclosure, not into the fold.
- [ ] Hero budget: about 0.75 of 1440x900 desktop, one 390x844 mobile viewport, with headline, core offer and primary CTA above the fold.
- [ ] Inventory CTAs and distinct messages. One primary CTA style.
- [ ] Preserve pricing, legal, limits, technical facts and genuine proof.
- [ ] No fabricated claims, testimonials or metrics.
- [ ] Preserve links, forms, analytics, keyboard access, headings, labels and SEO metadata.
- [ ] Check responsive overflow and focus if browser available.
- [ ] Measure section count, height in screens (desktop and mobile), per-section heights, screens to first CTA, screens to first product visual, distinct messages, CTA count. Word count last. Flag any section that grew.
- [ ] Self-review loop (up to 2 rounds): screenshots at 1440x900 and 390x844, skeptical critique (above-the-fold, 5-second test, hierarchy, tap targets), then fix.
- [ ] Run build/lint/typecheck/tests where available.
- [ ] Disclose unperformed checks and unmeasured outcomes.
- [ ] If height or section count moved less than about 15% and the map still has structural issues, do not ship trivial word trims. Say the page is already lean and name what you left, or restructure. In brutal mode, push further.

Word reduction alone is not proof of better UX or conversion. Structure first.
